# Автономна публікація: що лишилось увімкнути

Ярик 06.10.2026: «мене не влаштовує, що для публікації має працювати
ПК, публікація має бути автономною». Це правильно, і ось чому досі було
не так.

## Чому ламалось

Публікацію запускали два механізми, і обидва ненадійні:

**Планувальник Windows** — працює точно, але тільки поки машина не
спить. Заміряно: компʼютер прокидається між 07:39 і 10:37, а перше
вікно сторіс — 07:00–09:45. Кадр о сьомій ранку пролітає через раз.

**GitHub Actions за розкладом** — не тримає час узагалі. Заміряно
01–06.10.2026 на наших же запусках:

| | заявлено | фактично |
|---|---|---|
| запусків на добу | 72 | 1–5 |
| розрив між запусками | 15 хв | медіана 326 хв |
| найдовший розрив | — | 12,1 год |
| розривів довших за 2 год | — | 18 із 18 |

Вікно сторіс — від однієї до трьох годин. Планувальник із медіанним
розривом 5,4 години його просто перестрибує. Це не помилка
конфігурації: безкоштовний cron у GitHub так працює.

## Що вже зроблено

У `publish.yml` доданий вхід `repository_dispatch`. На подію Actions
запускається **одразу** — перевірено, запуск пішов за секунди. Тобто
механізм публікації автономний уже зараз; лишилось, щоб хтось надсилав
подію за розкладом.

## Що треба зробити тобі (10 хвилин)

### 1. Створити токен

GitHub → Settings → Developer settings → Personal access tokens →
**Fine-grained tokens** → Generate new token.

- Repository access: **Only select repositories** → `lisovik-instagram`
- Permissions → Repository permissions → **Contents: Read and write**
- Expiration: без терміну або рік

Скопіювати токен — він показується один раз.

### 2. Налаштувати пінгувальник

Будь-який сервіс, що вміє слати POST за розкладом. Безкоштовний і
перевірений — **cron-job.org**:

- Створити job, інтервал **кожні 10 хвилин**
- URL:
  ```
  https://api.github.com/repos/DeveloperrOp/lisovik-instagram/dispatches
  ```
- Метод: **POST**
- Заголовки:
  ```
  Authorization: Bearer <токен з кроку 1>
  Accept: application/vnd.github+json
  ```
- Тіло запиту:
  ```json
  {"event_type":"publish"}
  ```

Усе. Далі кадри йдуть самі, незалежно від того, чи увімкнений ПК.

### 3. Перевірити

Після першого спрацювання:

```
gh run list --limit 5
```

У списку мають зʼявлятись запуски з подією `repository_dispatch`
кожні 10 хвилин.

## Поки це не налаштовано

Локальний планувальник `lisovik-publish` лишається увімкненим як
резерв: щодня з 06:00 до 23:30, кожні 10 хвилин. Він публікує, коли
машина не спить. Журнал — `logs/publish_local.log`.

Два шляхи безпечні разом: маніфест спільний, а вже опубліковане
`publish.py` не чіпає.
