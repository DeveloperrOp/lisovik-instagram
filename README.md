# Instagram Лісовик

Конвеєр сторіс: каталог → контент-план → генерація → ревʼю → публікація.

## Швидкий старт

```bash
cd src

python fetch_catalog.py       # витягти каталог з Horoshop
python normalize_catalog.py   # відфільтрувати, порахувати
python build_plan.py 4        # скласти план на 4 тижні
python lint.py                # перевірити план ПЕРЕД генерацією
python generate.py --week 1   # намалювати підкладки
python compose.py --week 1    # накласти верстку
python review_bot.py send     # надіслати на ревʼю в Telegram
python publish.py --dry-run   # подивитись, що пішло б в ефір
```

## Сім типів сторіс

Типи відрізняються **версткою**, а не тільки фоном — інакше стрічка читається
як одне фото, повторене 28 разів.

| Тип | Вигляд | Задача | За тиждень |
|---|---|---|---|
| `product` | реальне фото товару, користь + фасовка | продати | 7 |
| `fact` | велика типографіка на приглушеній сцені | утримати досмотр | 7 |
| `howto` | три пронумеровані кроки | зняти барʼєр «що з цим робити» | 4 |
| `compare` | дві колонки | допомогти обрати | 3 |
| `review` | цитата клієнта | довіра | 3 |
| `ask` | фон під стікер запитань, **руками** | залучення | 2 |
| `mood` | сцена майже без тексту | перепочинок | 2 |

Сітка тижня — у `content/defaults.yaml`, ключ `grid`.

## Що де лежить

| Шлях | Що це |
|---|---|
| `content/types/*.yaml` | банки варіантів по типах — тут пишеться контент |
| `content/defaults.yaml` | CTA, дисклеймер, негатив, сітка, вікна, заголовки товарів |
| `content/content_plan.yaml` | згенерований план, руками не правити |
| `src/layouts.py` | верстка кожного типу |
| `src/config.py` | модель, бан-листи, безпечні назви, наявність |
| `out/pending/` | кадри, що чекають на ревʼю |

**Товарні сторіс не пишуться руками.** Вони збираються з каталогу: заголовок —
користь за категорією (`product_headlines`), підпис — форма і фасовка товару,
фото — з картки товару.

## Правила, зашиті в код

**Мухомор не публікується взагалі.** Ні текстом, ні в кадрі. Meta відносить
його до Entheogens, легальність в Україні значення не має, а бан каскадить на
весь Business Manager. Модель домальовує червону шапку в горошок сама — тому
негатив-констрейнт у кожній генерації плюс пункт у чек-листі ревʼю.

**Кава знята з продажу назавжди** — разом з лате, какао і матчею. Перевірка
в `is_discontinued()`.

**Назви товарів беруться не з каталогу.** Там вони містять медичні обіцянки:
«Курс Zen Mood: Для боротьби з тривожністю, апатією та депресією». У сторіс іде
«Курс Zen Mood». Не вдалося назвати безпечно — товар не публікується.

**Не рекламуємо те, чого немає на складі.** Обережно: «Немає в наявності»
містить підрядок «наявн», через що наївна перевірка вважає наявним увесь каталог.

**Дозування заборонені, фасовка — ні.** «по 0,5 г» не можна, «50 мл» можна.

**Походження — тільки «розфасовано в Україні».** Сировина імпортна.

**Генерація тільки в 2K.** На 1K українська кирилиця ламається.

## Тести

```bash
python test_lint.py       # 29 перевірок: не пропустити і не забракувати зайве
```

Лінтер має два способи підвести: пропустити порушення і забракувати нормальний
текст. Підрядковий пошук колись блокував «Публікуємо як є» — бо в ньому є
«лікує», а «ціКАВИть» вважав кавою.

## Обмеження Graph API

У сторіс через API доступні лише голе фото або відео. Не працюють:
стікер-посилання, опитування, музика, GIF. Тому все, що потребує стікера,
має `mode: manual` і публікується руками.

## Автопублікація

Два незалежні шляхи, маніфест у них спільний.

**1. Планувальник Windows (основний).** Завдання `lisovik-publish` запускає
`src/publish_local.py` кожні 10 хвилин з 06:00 до 23:30. Скрипт спершу
підтягує чергу з GitHub, публікує те, чиє вікно відкрите, і комітить
статус назад. Працює, поки увімкнений комп'ютер.

    Get-ScheduledTask lisovik-publish              # стан
    Get-ScheduledTaskInfo lisovik-publish          # останній запуск і код
    Start-ScheduledTask lisovik-publish            # запустити зараз

**2. GitHub Actions (резерв).** Той самий publish.py за розкладом cron.
🚨 На нього не можна покладатись як на основний: заявлено кожні 15 хвилин,
а фактичні розриви між запусками за 26-30.08.2026 — 91, 107, 185, 199,
248, 472, 535, 627, 847, 968 і 1054 хвилини. Медіана близько трьох годин,
найгірший випадок — 17,5 годин поспіль без жодного запуску. GitHub ставить
schedule у спільну чергу й при навантаженні пропускає. Саме через це вікна
в defaults.yaml широкі, а не тому що так зручніше.

Подвійної публікації не буде: publish.py бере лише `approved` і одразу
переводить у `published`, а локальний скрипт синхронізується з GitHub
перед кожним запуском.
